# AI 匹配模块说明

校园智能失物招领匹配系统 V3.0 · AI 能力集成

---

## 一、这个模块做什么

用户在平台上发布一条失物或招领信息后，系统自动在信息池里找出**最可能是同一件物品**的几条记录，给出相似度和判断理由，供本人人工确认。系统只做推荐，不自动判定归属。

对应基线功能：**FR05 结构化硬过滤 / FR06 文本匹配 / FR07 Top-3 候选与解释**。

---

## 二、为什么分两阶段

直接用大模型把全库几百条记录逐条比对，有两个问题：贵、慢。而且候选太多时模型注意力会被稀释，判断反而不稳。

所以拆成两段：

```
新发布一条信息
    │
    ├─① 结构化硬过滤（纯规则，0 成本）
    │     反向类型 / 30 天时间窗 / 排除已关闭
    │     几百条 → 几十条
    │
    ├─② 字面相似度粗排（TF-IDF，0 成本）
    │     同义词归一 + 中文 2-gram + 结构化加减分
    │     几十条 → 10 条
    │
    ├─③ 大模型语义精排（1 次 API 调用）
    │     理解"杯底贴纸"这类细节对应关系，输出理由
    │     10 条 → Top-3
    │
    └─④ 写回后端 → 前端「待确认匹配」页展示
```

**成本对比**：假设全库 300 条待匹配记录。直接比对是 300 次调用；两阶段后每次只处理 10 个候选，且一篇文章一次调用，实际约 30 次。**成本降低约 90%**，同时精排质量更高。

**技术取舍**（写报告时可直接引用）：粗筛用 TF-IDF 而不是向量数据库，是因为课程场景数据量在千级以内，引入 embedding 服务会增加部署复杂度和费用，收益不明显。如果日后数据量上万，把第 ② 步换成向量检索即可，第 ①②④ 步完全不用改——这就是分层的价值。

## 三、文件说明

| 文件 | 职责 |
|---|---|
| `coarse_filter.py` | 阶段一：硬过滤 + TF-IDF 粗排 + 同义词归一 |
| `llm_ranker.py` | 阶段二：大模型精排、JSON 解析容错、失败降级 |
| `main.py` | 流程编排 + HTTP 服务（可被前端/后端调用） |
| `test_eval.py` | 评测脚本，14 条用例覆盖代表性/边界/异常三类输入 |
| `.env.example` | 配置模板 |

依赖：**只用 Python 标准库**，不需要 `pip install` 任何东西。

---

## 四、配置

复制 `.env.example` 为 `.env`，填入大模型 Key：

```ini
LLM_API_KEY=sk-你的密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat

BACKEND_BASE=http://localhost:8000/api/v1
TOP_K=3
COARSE_LIMIT=10
RECALL_DAYS=30
MIN_SCORE=0.35
```

**不配 Key 也能跑**：系统会自动降级为纯字面相似度匹配，结果标记 `source=lexical`，前端会显示「字面相似」而不是「语义匹配」。这条降级路径是刻意设计的，保证演示时不会因为网络问题卡住。

> `.env` 文件在程序启动时自动读取（内置了一个极简解析器，不需要装 `python-dotenv`）。

## 五、接入任意大模型

服务用的是 OpenAI 兼容协议，换服务商只改 `LLM_BASE_URL` 和 `LLM_MODEL` 两行。

程序会自动处理各家 base_url 写法的差异（有的带 `/v1`，有的带 `/v4`，有的要补 `/v1`），你不用操心：

| 服务商 | LLM_BASE_URL | LLM_MODEL | 免费额度 |
|---|---|---|---|
| **智谱 GLM**（推荐） | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3-flash` | **免费额度**，128K 上下文 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` | 9B 以下永久免费 |
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` | 新用户 500 万 tokens，30 天 |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 每模型 100 万 tokens / 3 个月 |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | 新用户代金券 |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` | 完全免费（需本地显卡） |

**课程项目建议直接用智谱 GLM-4-Flash**：永久免费、不需要绑卡、中文强，128K 上下文对这个任务绰绰有余。额度焦虑直接消失。

这对应任务书「**不绑定单一平台**」的要求——代码里没有任何一家厂商的 SDK，换模型只改配置不改代码。

> 如果换厂商后报 404，说明 base_url 填错了。运行 `python main.py --status` 会打印出程序实际请求的完整地址，一眼就能看出问题。

## 六、运行方式

在 `ai` 目录下打开终端。

**⓿ 出问题时先跑这个（自检）**

```bat
python main.py --status
```

它会逐项告诉你：后端通不通、库里有没有物品、有没有跑过匹配、待确认页几条、大模型配没配，最后直接给出「需要处理」的清单。**页面是空的时候先跑这个，别猜。**

**① 跑一次全库匹配**（最常用，演示用这个）

```bat
python main.py --once
```

**② 只匹配某一条**

```bat
python main.py --item-id 1
```

**③ 只计算不写库**（调试用）

```bat
python main.py --once --dry-run
```

**④ 启动常驻服务**（后端/前端需要实时调用时）

```bat
python main.py
```
然后 `POST http://localhost:8100/match`，body 为 `{"item_id": 1}`。

**⑤ 跑评测**

```bat
python test_eval.py
python test_eval.py --verbose
```

## 七、评测结果

14 条用例，**14 通过 / 14（100%）**：

| 类别 | 数量 | 覆盖点 |
|---|---|---|
| 代表性输入 | 4 | 细节吻合、同义词归一、品牌型号、反向匹配 |
| 边界输入 | 5 | 同类不同物、时间超窗、已关闭记录、描述极简、同地点不同类 |
| 异常输入 | 5 | 空池、字段缺失、时间格式非法、超长文本、未知类型 |

**修正记录**（写报告可以用，体现"验证驱动改进"）：

初版粗排只有加分没有扣分，导致两个误报：

| 用例 | 修正前 | 修正后 | 原因 |
|---|---|---|---|
| 黑色保温杯 vs 白色保温杯 | 0.52 误报 | **0.22** | 颜色冲突未扣分 |
| 充电宝 vs 耳机 | 0.40 误报 | **0.00** | 类别冲突未判死 |

修正做法：类别明确冲突直接判 0；颜色冲突扣 0.30、品牌冲突扣 0.15、地点不同扣 0.08。正例分数基本不变（R1 从 0.98 → 0.92，R4 达 0.997）。

## 八、异常处理清单

对应任务书「异常处理」要求：

| 异常情况 | 处理方式 |
|---|---|
| 未配置 API Key | 降级为字面相似度，`source=lexical`，前端明确标注 |
| 网络超时 / 连不上 | 重试 2 次（1.5s、3s 退避），仍失败则降级 |
| Key 无效（401/403） | 不重试，直接降级，避免无效等待 |
| 模型返回非 JSON | 尝试从代码块、前后文中提取 JSON；失败则降级 |
| 模型返回分数是字符串 | 强制 `float()` 转换 |
| 模型返回分数越界 | 裁剪到 `[0, 1]` |
| 模型返回不存在的候选 id | 丢弃（防幻觉污染） |
| 模型漏判某些候选 | 剔除未返回项，其余照常使用 |
| 时间字段格式非法 | 回退到当前时间，不抛异常 |
| 字段为 None | 全部按空串处理 |
| 超长文本（2000+ 字） | 正常处理，实测无超时 |

**所有异常都不会让服务崩溃，最差情况是降级为字面匹配。**

## 九、给复核同学看的验证要点

按任务书「AI 实现者不能独自验收」要求，请复核时重点看：

1. **跑一遍 `python test_eval.py`**，确认 14/14 通过
2. **故意把 Key 写错**再跑，确认程序降级而不是崩溃报错
3. **在页面上发布一条新信息**，看是否自动出现在「待确认匹配」页
4. **检查理由是否可信**——随机抽 3 条，看理由里提到的字段是否真的对得上
5. **点「忽略」**，确认该候选不再出现

## 十、已知限制

- 同义词表写死在 `coarse_filter.py` 的 `SYNONYM_GROUPS` 里，目前 12 组，覆盖校园常见失物。扩充需要改代码（后端有 `synonyms` 表，后续可以改成从库里读）。
- 中文字级 2-gram 对错别字不敏感（"保温杯" vs "温保杯" 能部分匹配，但 "水杯" vs "水盃" 匹配不上）。
- 大模型判断带随机性，`temperature=0` 已尽量压低，但同一对记录多次调用分数可能有 ±0.05 波动。
- 单次请求最多处理 `COARSE_LIMIT`（默认 10）个候选，再多会超出模型输出长度。
